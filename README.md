# مسكوب · Maskob

أتمتة عمليات مسكوب: تطبيق الطلبات بين مستودع مسكوب والفروع، في صفحة واحدة (`index.html`).

## سير العمل
1. **الفرع** يدخل برمزه، يختار الأصناف بالكميات (توريد من المستودع أو إرجاع)، ويرسل الطلب.
2. **الإدارة** تراجع الكميات وتعتمد الطلب أو ترفضه.
3. **المستودع** يجهّز الطلب كقائمة مهام (علامة ✓ لكل صنف) ثم يرسله.
4. **الفرع** يستلم ويسجّل الكميات المستلمة والملاحظات، وتظهر الفروقات تلقائياً.

## المزايا
- رمز دخول خاص لكل فرع وللإدارة وللمستودع، تديره الإدارة من «الإعدادات».
- 4 لغات: العربية، English، বাংলা، اردو.
- توقع الطلب القادم لكل فرع واحتياج المستودع لـ 7 أيام (بعد 7 طلبات معتمدة لكل فرع).
- تقرير يومي للإدارة مع نسخه نصاً لواتساب.
- تصدير إكسل للطلبات والتقرير والتوقعات.
- قائمة أصناف مسكوب (حوالي 170 صنفاً في 14 فئة) من ملف طلب فرع القطيف.

## التشغيل
التطبيق منشور على Firebase Hosting:
**https://fllow-maskob.web.app**

- قاعدة البيانات: Cloud Firestore في مشروع `fllow-maskob`.
- كل جهاز يسجّل دخولاً مجهولاً (Anonymous) في Firebase، وإدخال رمز الدخول يفتح «جلسة» تتحقق منها قواعد الأمان على الخادم.
- الفرع لا يرى إلا طلباته، ورموز الدخول لا تقرؤها إلا الإدارة. التفاصيل في `firestore.rules`.

### النشر
```powershell
firebase deploy --only "firestore:rules,hosting" --project fllow-maskob
```

### هيكل البيانات
| المسار | المحتوى |
|---|---|
| `orders/{id}` | الطلبات بكل مراحلها |
| `config/main` | قائمة الفروع |
| `config/pins` | بصمات رموز الدخول (للإدارة فقط) |
| `codes/{hash}` | ربط بصمة الرمز بالدور أو الفرع (قراءة بالبصمة فقط) |
| `sessions/{uid}` | جلسة كل جهاز |

## الملفات
- `index.html` — التطبيق كاملاً (الواجهة، الأصناف، الترجمات، الشعار مضمّن).
- `firebase-config.js` — إعدادات تطبيق الويب في Firebase (معرّفات عامة وليست أسراراً).
- `firestore.rules` — قواعد الأمان لقاعدة البيانات.
- `firebase.json`, `.firebaserc` — إعدادات النشر.
- `maskob-wordmark.png` — شعار مسكوب (أبيض وبرتقالي على خلفية شفافة).
